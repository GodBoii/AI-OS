## Image tool

The presentation agent now receives `create_presentation_image(prompt, template, aspect_ratio)`. It uses the app's existing OpenRouter image client. The template adds matching art direction, and the client requests medium quality with a verified provider capability. Supported shapes are `3:2`, `2:3`, and `1:1`. It reports unsupported options instead of silently changing them.

The tool returns a local PNG path, actual dimensions, provider/model/cost metadata, and a model-visible image for inspection. Identical requests reuse the saved asset. The agent generates needed assets first, then submits the complete deck in one compact export call. Image bytes do not appear in textual tool results. Failed generation returns an error and no invented path.

Use the returned path on a `title` or `image` slide:

```json
{
  "type": "image",
  "title": "Make the handoff visible",
  "image_path": "<path returned by create_presentation_image>",
  "image_fit": "contain",
  "bullets": ["Give every request a named owner"],
  "caption": "AI-generated illustration"
}
```

`contain` is the default and preserves the complete subject. `cover` is an explicit option for intentional photographic cropping. The renderer uses actual image dimensions, keeps fractional geometry, normalizes EXIF rotation, and converts WebP/JPEG assets to PNG. Text occupies a separate region and goes through the usual geometry, contrast, and rendered-overflow checks. Generated images should not contain slide titles, statistics, or diagram labels; those remain editable text.

## Verification

The final check passed 100 Python tests and 5 JavaScript/browser tests. Ruff checks and JavaScript syntax checks passed for the changed toolkit modules.

The review used identical content across nine decks, with a real generated illustration on their covers and image slides. Chromium checked all layouts. Microsoft PowerPoint opened and rendered 81 slides, then measured their native text bounds. The final audit found zero overflowing text boxes. Native review caught a Georgia cover heading and a Consolas chart callout that needed additional space. It also led to cleaner header-rule placement.

Tests cover distinct geometry and typography independently of color; image-tool registration on the actual agent; provider quality/aspect options; generated bytes saved locally and embedded in a PPTX; cache reuse; portrait/landscape/square fitting; crop bounds; EXIF rotation; WebP normalization; broken assets; and provider failure handling. Desktop and mobile browser checks exercise the real picker, image loading, template selection, focus trapping, and Escape close.

## Live provider result and deployment

The configured app image provider returned **HTTP 402** during the live test. Its account credits or key limits need attention before successful generation can be verified through that account. The implementation reports this failure correctly. The review illustration came from Codex's built-in `image_gen`, not from a successful app-provider request. The successful image-tool tests substitute only the unavailable provider and exercise real saving, normalization, and PPTX embedding.

The sample prompt asked for a tactile 3D operations workspace with blank cards moving through inbox, review, and completed trays. It specified pale blue/white with cobalt/teal details, landscape composition, and no text or statistical claims. The generated asset is saved as `presentation-toolkit-output/design-review/operations-illustration.png`.

Changes are local. The Docker image needs a rebuild for the new font fallbacks and Python/JavaScript modules. Windows PowerPoint rendering was verified; Linux font substitutions and other Office versions can change wrapping. Deployment and live cloud persistence were not exercised in this pass.
