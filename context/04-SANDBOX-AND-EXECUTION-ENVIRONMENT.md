# Sandbox & Execution Environment

This document explains the isolated execution environment where generated code and terminal scripts run, and how the sandbox manager coordinates container lifecycles.

---

## 🏗️ Sandbox Architecture

To prevent arbitrary code execution from accessing the host operating system, AI-OS isolates all file creations and terminal executions inside a Dockerized sandbox:

```
+------------------------------------------------------------+
|                       PYTHON BACKEND                       |
|                 (Host or Backend Container)                |
+-----------------------------+------------------------------+
                              |
                     REST API | (SANDBOX_API_URL)
                              v
+------------------------------------------------------------+
|                      SANDBOX MANAGER                       |
|           (FastAPI Service running on Host/Docker)         |
+-----------------------------+------------------------------+
                              |
                    Docker    | (Docker SDK / API)
                    Exec/Copy |
                              v
+------------------------------------------------------------+
|                      DOCKER SANDBOX                        |
|            (Custom Ubuntu Container, /workspace)           |
+------------------------------------------------------------+
```

1.  **Sandbox Manager:** A lightweight FastAPI server running in `sandbox_manager/main.py`. It listens for requests to create sandbox sessions, execute commands, and transfer files.
2.  **Isolated Ubuntu Environment:** Spun up dynamically by the Sandbox Manager. It has an internal directory `/workspace` which acts as the root sandbox directory.
3.  **Sandbox Tools Interface:** A Python class `SandboxTools` in [sandbox_tools.py](file:///c:/Users/prajw/Downloads/app/AI-OS/python-backend/sandbox_tools.py) that acts as the client-side bridge between the Agno AI Agent and the Sandbox Manager.

## 🛠️ Sandbox File & Command Operations

When the AI Agent needs to read, write, or execute code, it calls methods inside [sandbox_tools.py](file:///c:/Users/prajw/Downloads/app/AI-OS/python-backend/sandbox_tools.py). These operations flow through the Sandbox Manager:

### 1. File Writing (`write_file` / `create_file`)
*   *Action:* Converts file contents to bytes and performs a `POST` request to `/sessions/{sandbox_id}/files`.
*   *Downstream Effect:* The Sandbox Manager writes the byte data directly into the target path inside the container's `/workspace` folder, ensuring directory sub-structures are created if missing.

### 2. File Editing (`edit_file`)
*   *Action:* The agent provides search-and-replace block targets.
*   *Downstream Effect:* The sandbox manager reads the target file, replaces the exact content block, and writes it back. This minimizes data transfer size compared to rewriting the entire file.

### 3. Command Execution (`execute_in_sandbox`)
*   *Action:* Sends bash scripts to `/sessions/{sandbox_id}/execute`.
*   *Downstream Effect:* The Sandbox Manager calls the Docker REST API `Container Exec` endpoint. It spins up an execution process inside the container, monitors it until completion or timeout (default 310 seconds), captures the exit code, and returns the standard output (`stdout`) and standard error (`stderr`) streams to the backend.

## 🔍 Artifact Detection & Upload Pipeline

When files (such as HTML layouts, graphs, SVGs, or PDF reports) are generated by running code, the sandbox automatically extracts and displays them to the user:

```
[Agent runs script] ---> [Filesystem changes detected]
                                 |
                                 v
                [New/modified files are copied out]
                                 |
                                 v
            [Uploaded to Supabase storage bucket 'media-uploads']
                                 |
                                 v
      [Socket event 'artifact_detected' emitted to client]
                                 |
                                 v
    [js/artifact-handler.js displays preview panel in front-end]
```

1.  **State Snapshotting:** Before running a terminal command, the backend tracks the files inside the container's workspace using `_get_sandbox_files()`.
2.  **Change Detection:** After execution, `_detect_and_emit_artifacts_async()` compares the file state against the snapshot to detect new or modified files.
3.  **Extraction & Upload:** The detected files are downloaded from the container's filesystem and uploaded to the Supabase `media-uploads` storage bucket.
4.  **Frontend Notification:** The backend emits an `artifact_detected` Socket.IO event to the client room. The client-side `artifact-handler.js` parses this event and displays the file (e.g. rendering interactive HTML pages or images) side-by-side with the chat.
